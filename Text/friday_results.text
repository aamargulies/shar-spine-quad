**What's worth noting vs Lemire's framing**

- Lemire's original result: SIMD Quad beats `std::binary_search` at n=4096 on both EMR and M4, with a bigger win cold on M4 and a bigger win warm on EMR. Our data reproduces that: EMR cold 2.74×, M4 cold 4.85× over his own algorithm once we apply the **spine** (his next-step hint in the article conclusion: "I suspect that we can do even better").

> Correction 2026-10-11: these ratios use the retired unroll's cells and bench.cpp's then-unflushed "cold" column (no cache flush before 2026-10-11; the ~35 MB footprint is LLC-resident on every host but the Pi 5), so they measure LLC-hit rather than DRAM-cold behaviour (Text/corrections_2026-10.md §5). Archived levels (regenerated bench_table.txt, per-cell medians of 5 runs, n=4096 cold): EMR reference 71.0 → general-n spine 37.2 → compile-time n=4096 24.36 ns; M4 Max reference 31.5 → general-n spine 6.5 ns (compile-time n=4096 21.94).
- The single biggest optimization on every host was the spine (sequential streaming read of block-last-element keys) rather than anything SIMD-specific.
- The 2026-05-01 re-benches turned up a real surprise: on a Roaring-set workload (outer search across container keys + inner search within), **Shar's 1971 branchless binary search** beats the outer spine on every host, including the two Intel cores where we expected the LLC streamer to make outer-spine unbeatable. SKX: F beats D by −9.7% warm / −22.9% cold. EMR (measured 2026-05-01): F beats D by −21.2% warm / −40.0% cold — the biggest x86 margin. All five uarchs (Pi 5, M4, SKX, EMR, GV4) converge on variant F (Shar outer + compile-time-n=4096 inner) as the right ship for the Roaring workload.

- Two predictions were refuted by these measurements. (1) "Intel's LLC streamers will love the outer-spine sequential multi-line pattern so the outer spine will win on x86." Wrong on both SKX and EMR. (2) "The EMR VBMI2 path doesn't downclock, so even if SKX loses to Shar the outer spine will still win on EMR." Also wrong — EMR actually gave Shar the *biggest* x86 margin. The likely unifying mechanism is just that the K=512 outer key spine is only 16 × 64-B = 1 KB (8 × 128-B on M4), too short for any stride prefetcher to matter, so the outer spine's dependent pointer chase is pure critical-path cost on every host. Shar's ~9-load cmov chain replaces that chase with independent loads that issue back-to-back on any OoO core with enough load AGUs.

> Correction 2026-10-11: Shar's outer search is a serial cmov chain (load → compare → csel → load, each address depending on the previous select), not independent loads issued in parallel; it wins hot because it has no branch mispredicts and no side structure, and on cold data the branchy std::lower_bound outer (A, C) speculates ahead across mispredicted branches instead, which is why C is the cold winner on EMR and GV4 (Text/corrections_2026-10.md §5).
